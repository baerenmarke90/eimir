# Local AI for automatic relationship recaps

Owner: #1528. Automatic monthly/yearly editions run on the existing PostgreSQL
queue. Model inference only supplies a short title/introduction from up to eight
selected shared text excerpts. There is no inference on a GET, image recognition,
vector database, Redis, Celery, GPU toolkit or Python ML environment.

## Runtime contract

The canonical `compose.yaml` contains the optional `recap-ai` profile. The service
uses upstream Ollama 0.40.12, pinned to its multi-platform registry digest. CPU
execution is limited to two cores and 4 GiB maximum container memory. This is a
resource ceiling, not a measured RAM requirement or throughput promise. The
standard upstream image includes acceleration libraries; no GPU device/runtime
is enabled or required. The Qwen3 1.7B Q4_K_M model download is approximately
1.4 GB, in addition to runtime image/cache storage.

Ollama is MIT; Qwen3 is Apache-2.0. Model/runtime artifacts are third-party
operator downloads rather than part of the application images. Preserve their
notices if redistributing. Sources and the current reuse decision are recorded
in [the design contract](product/design/automatic-relationship-recaps.md).

`OLLAMA_NO_CLOUD=1`, one loaded model, one inference at a time, a one-request
queue, 4096-token context, no thinking, CPU-only inference options, bounded JSON
output and `keep_alive: 0` apply. The model is unloaded after a request. No model
API port is published or added to the reverse proxy. The worker uses its
operator-configured internal HTTP origin without HTTP proxies or redirects.
Only private addresses/internal service names are accepted. No product API
accepts an inference endpoint or sends owner-only content to the model.

Settings on **both API and worker**:

```dotenv
EIMIR_RECAP_AI_URL=http://recap-ai:11434
EIMIR_RECAP_AI_MODEL=qwen3:1.7b-q4_K_M
EIMIR_RECAP_AI_TIMEOUT_SECONDS=90
```

An empty URL disables inference. Failed/missing models, timeouts and invalid or
oversized output produce the complete rules/localized-template edition. No API
subscription or token bill applies; existing host CPU, storage and power remain
real costs. Actual German wording quality and cold-start latency must be measured
on the operator's host before relying on AI prose. Structured output limits the
shape and source identifiers; it cannot mathematically establish factual truth.
The original authored content remains visibly distinct from the introduction.

The editorial request is a short album caption rather than fictional storytelling:
at most ten title words and two introductory sentences, forty introduction words,
64 title characters and 240 introduction characters. Source kind, occurrence date
and the existing bounded original text provide context; identical title/excerpt
text is sent once. The prompt explicitly rules out invented authors/recipients,
third-party reactions, inferred day-long emotions, superlatives and filler.
The parser rejects overlong/blank/multiline copy, repeated four-word phrases,
duplicate or unknown source references, and numeric claims absent from the cited
original wording. Source dates and identifiers cannot justify numbers in prose.
Rejected copy uses the complete rules fallback with no extra inference retry.
These checks constrain known failure modes; they are not semantic fact checking,
and a short false claim can still pass. Assess real German model output on the
operator's host. The model and hardware requirements have not changed.

Existing editions are not regenerated by this wording change. In particular,
retained editions and manually customized selections must remain untouched.

## Canonical Self-Hosted deployment

Use the normal release identity/environment first; do not bypass its guard:

```bash
docker compose --profile self-hosted --profile recap-ai up -d recap-ai
docker compose --profile recap-ai exec -T recap-ai ollama pull qwen3:1.7b-q4_K_M
docker compose --profile recap-ai exec -T recap-ai ollama list
# Set the three settings above in the existing operator environment.
docker compose --profile self-hosted --profile recap-ai up -d
```

Do not run `down -v`, replace application data volumes, or bootstrap an existing
instance. Inference is optional, so application readiness never depends on the
model server. A model download failure must not prevent normal product use.

## Existing Arcane private test channel

The supplied `eimir-test` Compose is generated by `deploy/eimir-test`. Its four
application services, separate database, external networks, secret expressions
and data volumes must remain owned by that Git Sync project. The channel
exporter forwards all three optional settings without freezing an operator URL
or secret into a published application image.

Run the optional AI service in its own Arcane project on the existing
`eimir-test-data` external network, with the unique network alias
`eimir-test-recap-ai`. This avoids Git Sync removing a manually inserted service.
Use the **same canonical service definition** from the optional profile, with
its profile removed, a dedicated model volume and that external network. Do not
connect it to `mailcow-proxy` or publish port 11434.

On the main Arcane project's existing Environment add:

```dotenv
EIMIR_RECAP_AI_URL=http://eimir-test-recap-ai:11434
EIMIR_RECAP_AI_MODEL=qwen3:1.7b-q4_K_M
EIMIR_RECAP_AI_TIMEOUT_SECONDS=90
```

Deploy the AI project, open its `recap-ai` service console and run:

```bash
ollama pull qwen3:1.7b-q4_K_M
ollama list
ollama ps
```

From a host shell with the AI project's Compose file:

```bash
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json config --quiet
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json pull
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json up -d
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json exec -T recap-ai ollama pull qwen3:1.7b-q4_K_M
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json exec -T recap-ai ollama list
docker compose -p eimir-test-recap-ai -f arcane-ki.compose.json ps
```

After merge and required main checks, let the existing private-channel publisher
produce new backend/Web digests and Arcane Git Sync redeploy the main project.
Migration `0093` is additive and runs through existing `cloud-migrate` readiness
dependencies. An old digest cannot contain the feature: do not redeploy the
operator's pasted old digests as proof of this change. Check `channel.json`'s
source SHA and the running images before acceptance. See
[the channel runbook](PRIVATE-TEST-CHANNEL.md).

The worker automatically checks active Pro Spaces every six hours, prepares the
current month/year and available most recent completed periods, and only queues
changed periods once. Opening the library also schedules preparation without
waiting for the next scan. Saved editions are not overwritten. Current periods
are explicitly partial; annual selection uses the entire calendar interval.

## Verification and rollback

Check API/worker readiness through Arcane; open More → Relationship passport,
read monthly and yearly editions, follow a source and return, save a private
draft, deliberately share words and retain an edition. The model can be stopped
to verify fallback independently. `ollama ps` should show no retained loaded model
after generation. Logs contain operation/status metadata rather than prompts.

To disable inference, empty `EIMIR_RECAP_AI_URL` for API/worker, redeploy the main
project, then stop the separate AI project. Existing editions and ordinary
application use remain available. Retain the model volume for a later restart.
Database rollback is separate from image rollback; do not downgrade a database
containing recap artifacts without first handling their essential export.
