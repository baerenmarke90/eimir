## 2. Binding #824 interpretation used

Classification applies the final standard in this order: privacy/security → accessibility → comprehensibility/usability → smartphone-first invariant → domain product decision → design-system consistency. For normal couple-facing surfaces, Compact/smartphone is the normative product reference; Web is an adaptation. Dense metadata rows, equal dashboard tiles, uncomposed field stacks, generic rectangles and table/admin/CRM composition are prohibited unless specifically justified. Primary screens require a recognizable human/emotional focal point. Lists for Memories, Heart Moments, Milestones, Wishes, Plans, People, Places, Collections and Chapters must be justified by the human task rather than by the DTO shape.

## 5. Current blockers that are not optional design taste

### Android privacy baseline requires revalidation after #683

The 2026-09-09 Android baseline classified Heart Moments owner screens, Related Persons, Important Dates and Profile Preferences as privacy FAILs because the then-current `isSecureRoute()` policy did not cover them. #683 has since merged through PR #835. This Web-focused reconciliation does not change Android rows; a separate coordinator pass must verify the exact current route coverage and reclassify every affected Android row before further remediation is sliced.

### Android CRUD/dialog concentration

The dominant #824 product-pattern debt is not Android navigation itself; it is the repeated combination of `LazyColumn` + inline create + repeated `Surface` records + visible management actions + `AlertDialog` editing. #824 v2.0 explicitly prevents existing component reuse from serving as a design justification. Each affected domain must choose the human mobile task first.

### Web reconciliation result

Web has no remaining design/composition FAIL row in this matrix after #832 replaced the People/Important-Date record editors and metadata-led list, and #943 hardened their interaction behavior. The previous 400% reflow defects were fixed by #815 and Quick Create was corrected by #826. This classification result does not waive the remaining full #825 runtime sweep for rows still marked `PENDING`.
