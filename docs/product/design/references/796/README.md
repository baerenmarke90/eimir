# #796 Optional product orientation: design preflight

Baseline: `origin/main` at `9761f923aef4bcfc10191d9005d39c1d1ac1a763` (2026-09-26). Reviewed the actual `MoreOverviewPage`, `AppShell`, `QuickCreateMenu`, Today, Story, and Planning routes on that baseline before generating [the Compact reference](optional-tour-compact.png). The current More screen has three groups: personal (Profile, Private Area), shared (Insights, People, Places, Collections, Games), and utility (Notifications, Activity, Settings). The reference adds one orientation entry to the existing utility group and a nonmodal orientation card. It invents some supporting row copy and shows the card on More; those details are illustrative, not existing product behavior or binding implementation. All actual destinations, permissions, shell actions, and safety copy remain present.

## Product Reference and Mobile Interaction Contract

Follow Product Reference v1 R4/R2/R3/R5, the More/Settings screen template, and the existing four-destination shell. The shared relationship and real content remain the focal points. The orientation is a small optional overlay inside the shell, with one concept at a time and a route action pointing to the real page. Primary action is seeing that surface. Dismiss is always visible and does not block any route. Compact at 360/390/430 px uses a bottom-anchored card above navigation; Expanded retains a bounded card without a new information architecture. Tapping outside or choosing any ordinary product action leaves the tour; replay remains under More. No typing, setup checklist, forced next, fake content, or tutorial-only safety instruction.

Open from More or the first-use prompt → read a single concept → visit the real page → advance or dismiss → return to normal navigation. A normal task can always proceed without completing the tour. Keyboard and assistive technology encounter a named region with normal buttons and links, no focus trap; focus goes to the newly opened region and returns to the replay trigger on an explicit close where still mounted. The card never uses spotlight-only meaning. Movement is optional and suppressed for reduced motion. Loading is unnecessary for local state; storage failure falls back to replayable in-memory state. Success is the destination opened, not a score.

## Reuse, business, and cross-cutting decisions

Reuse the current shell routes, More destination row, existing Quick Create behavior, localization, semantic tokens, and the existing browser/Capacitor storage capability. An account preference API, third-party tour library, and onboarding state machine would add migration, data flow, or focus complexity for four static concepts. No new provider or dependency; license/ToS, Cloud/Self-Hosted, cost, privacy, and fallback therefore remain local to the existing application. Persist only a versioned seen/dismissed boolean per account and Space on the current device; replay resets the in-memory flow and keeps this flag as seen. It never contains personal content and cannot leak to the partner. Web and Android use the same Capacitor-wrapped UI and storage semantics. This is Free/Core help, no entitlement, managed cost, quota, or downgrade effect; no feature-matrix change.

The orientation does not replace #498 new-Space move-in, does not alter invitation/authentication, and never owns privacy, destructive, validation, permission, or offline warnings. It adds no permanent subtitles to Wir, Momente, Planen, or editors. Accessibly labeled controls, logical focus, reflow, locale-driven copy, reduced motion, and no sensitive telemetry are required. Visual evidence before merge must show Compact/Expanded, Light/Dark, text scaling, and the open → visit → dismiss → replay flow.
