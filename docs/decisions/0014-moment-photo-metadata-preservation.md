# ADR 0014: Preserve readable metadata in selected moment photos

Status: accepted Product Owner instruction in the implementation chat (2026-10-26), following #1459. The canonical location feature is already merged in #1465; this is a narrow follow-up, not a replacement implementation.

The owner explicitly allowed metadata to remain in the photo. Local and explicitly selected external photos enter the existing Memory/HeartMoment draft uploader, which now requests primary-image metadata preservation. The worker retains readable EXIF and ICC profiles where the validated output codec supports them. Raw uploaded container segments are never copied wholesale; unusable optional metadata may be omitted. Pixel decoding, format, dimensions, resource limits, encrypted storage and parent-based authorization remain mandatory.

The transport flag is independent of the account's location-association preference. OFF still prevents location extraction/staging/association according to #1465, but does not scrub the photo's retained metadata. A downloaded/shared authorized primary file can therefore contain capture time, GPS and device information. Removing a Place relation likewise does not scrub the file. Already sanitized historical files are not recoverable.

The flag defaults false for old clients and unrelated uploads. Profile/avatar and other non-moment consumers keep their existing metadata removal. Thumbnail derivatives remain metadata-free and apply orientation to pixels for preserved originals. No original raw upload is kept as a second file, no new derivative or retention period is added, and quota accounting continues to use the validated stored size.

The setting UI receives only an explanatory localized sentence under the existing switch. There is no new control, per-entry confirmation, provider call, native permission, tracking behavior, entitlement or price boundary. This remains within existing Free/Core moment/media behavior and is identical for Cloud and Self-Hosted. Parent visibility, #1465's separate encrypted/consumed GPS staging, manual-choice protection, tenant/lifecycle locks and crypto/endpoint audit registries are preserved.

Reuse: existing Pillow/Pillow-HEIF decoding/encoding and EXIF support, protected AttachmentPayload, upload transport, shared settings and generated OpenAPI client. No new dependency or provider agreement. Current #1459 R5 preflight and generated Compact metadata-help reference were linked before the copy change; the established live layout and actions take precedence over illustrative composition. Test real JPEG/PNG/WebP/HEIF metadata round trips, independent extraction/retention, invalid optional metadata, clean/oriented previews, default-off unrelated contexts, encrypted upload/read binding and selected-photo client flags.
